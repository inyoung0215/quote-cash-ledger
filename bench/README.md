# 락 전략 비교 (작업 예정)

사용 가능한 자원 하나를 여러 요청이 동시에 가져가려 할 때,
네 가지 방법의 처리량과 지연을 같은 조건에서 측정한다.

| 방법 | 기대 |
|---|---|
| `SELECT ... FOR UPDATE` | 확실하지만 같은 행에 대기가 쌓인다 |
| `FOR UPDATE SKIP LOCKED` | 잠긴 행은 건너뛴다. "아무거나 하나"에 적합 |
| 조건부 UPDATE (`WHERE status='A'`) | 외부 의존 없음. 실패 시 재시도, 같은 행 재선택 주의 |
| Redis `SETNX` | 빠르지만 Redis 장애 때 방어가 사라진다 |

측정할 것: p50 / p95 / p99, 처리량, 실패율, 재시도 횟수.

평균이 아니라 **꼬리 지연**을 본다. 평균은 대기가 쌓이는 걸 숨긴다.
