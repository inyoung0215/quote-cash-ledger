# ADR-0001. 보류 모델 vs 차감-환급 모델

## 맥락

숨고가 고수에게 공개한 안내 기준으로 견적 캐시는 이렇게 동작한다.

- 고수가 견적을 보낼 때 캐시가 쓰인다
- **고객이 열람했을 때만** 비용이 확정된다
- 48시간 안에 열람되지 않으면 **보너스캐시로 돌려준다**

같은 정책을 두 가지로 구현할 수 있다.

| | 차감-환급 모델 | 보류 모델 (선택) |
|---|---|---|
| 발송 시점 | 잔액에서 바로 차감 | 차감 없음. 보류 버킷만 증가 |
| 미열람 만료 | 보너스캐시로 **적립** | 보류만 해제. 재원 변환 없음 |
| 상태 변경 횟수 | 2회 (차감 → 적립) | 1회 (보류 → 확정 또는 해제) |
| 재원 | 유상 → 보너스로 **바뀐다** | 그대로 |

## 결정

**보류 모델**을 택했다.

## 이유

1. **미열람은 아무 일도 없던 것과 같아야 한다.** 차감-환급 모델은 유상캐시로 나갔다가
   보너스캐시로 돌아온다. 보너스캐시에 유효기간이 있다면 고수는 미열람만으로 손해를 본다.
   재원이 바뀌지 않는 쪽이 고수에게 정확하다.
2. **결과가 확정되지 않은 거래를 확정된 것처럼 기록하지 않는다.** 발송 시점에는 과금될지
   아직 모른다. 모르는 것을 확정하지 않는다는 원칙과 맞다.
3. **되돌릴 일이 생기지 않는다.** 보상 로직을 정교하게 만드는 것보다 보상할 필요가 없는
   구조가 안전하다.

## 대가

- 사용 가능 잔액이 `잔액 - 보류 합계` 라서 고수 화면에 "잔액"과 "사용 가능"이 다르게 보인다.
  설명이 한 단계 더 필요하다.
- 보류 버킷을 재원별로(`held_paid`, `held_bonus`) 따로 둬야 해서 컬럼이 늘었다.

## 숨고가 환급 모델을 택했다면 그 이유는 무엇일까

추측이지만, 아마도

- 발송 시점에 잔액이 실제로 줄어야 고수에게 직관적이고
- 보너스캐시 적립이 재참여 유인이 되며
- 회계 처리상 "쓴 돈"과 "받은 보너스"를 나누는 편이 단순하기 때문

이라고 본다. **실제로 어느 쪽이고 왜 그렇게 정하셨는지 여쭤보고 싶다.**

## 재원 분배 순서

보너스캐시를 먼저 쓴다. 보너스는 통상 유효기간이 있어 먼저 소진시키는 편이 고수에게 유리하다.
다만 이건 기술 판단이 아니라 **정책**이므로, 분배 결과를 원장에 `paid_delta` / `bonus_delta` 로
남겨 사후에 설명할 수 있게 했다. 차감 순서가 곧 고수의 손익이다.
