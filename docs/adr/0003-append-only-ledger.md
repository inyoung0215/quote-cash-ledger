# ADR-0003. 원장은 덮어쓰지 않는다

## 결정

`cash_ledger` 는 **추가만 한다**. 어떤 행도 UPDATE 하지 않는다.
보류(HOLD) · 확정(CAPTURE) · 해제(RELEASE)를 각각 한 줄씩 남긴다.

잔액은 `pro_cash_account` 에 따로 유지하되, 원장에서 재구성한 값과
언제나 일치해야 한다 (`assert_ledger_matches_account`).

## 이유

**고수가 "왜 이 금액이 빠졌냐"고 물었을 때 답할 수 있어야 한다.**

잔액만 들고 있으면 그 순간 설명할 근거가 사라진다.
특히 이 도메인은 발송 → 열람 → 과금 사이에 최대 48시간이 있어서,
고수가 기억하는 시점과 돈이 빠진 시점이 다르다. 이력이 없으면 설명이 불가능하다.

두 번째 이유는 **대사(對査)가 가능해야 한다**는 것이다.
잔액과 원장을 따로 두고 둘이 맞는지 확인할 수 있어야, 어긋났을 때 어느 쪽이 틀렸는지 안다.
하나만 있으면 틀렸다는 사실조차 알 수 없다.

## 구현 노트

- 분배 결과를 `paid_delta` / `bonus_delta` 로 나눠 기록한다.
  어느 재원에서 빠졌는지가 고수 손익이다 (ADR-0001).
- `UNIQUE(quote_id, entry_type)` — 같은 견적에 같은 종류의 원장이 두 번 쌓이지 않는다.
- 잔액 컬럼을 두는 건 성능 때문이다. 원장을 매번 합산하면 건수가 쌓일수록 느려진다.
  대신 불변식 점검을 테스트가 항상 호출한다. 운영이라면 대사 배치로 돌려야 한다.
