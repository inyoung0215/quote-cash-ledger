# ADR-0006. async 엔드포인트에는 비동기 드라이버를 쓴다

## 결정

FastAPI(ASGI) + SQLAlchemy 2.0 async + **aiomysql**.

## 이유

이벤트 루프는 스레드 하나로 돈다.
`async def` 안에서 **동기** DB 드라이버(PyMySQL 등)를 호출하면
그 호출이 끝날 때까지 루프 전체가 멈추고 다른 요청도 전부 대기한다.
동시성을 얻으려고 async 를 썼는데 오히려 처리량이 떨어진다.

Spring WebFlux 의 리액티브 체인 안에 JDBC 호출을 넣으면 이점이 사라지는 것과 같은 원리다.

## 선택지

| | 판단 |
|---|---|
| `async def` + 비동기 드라이버 | **선택.** 일관되고, ASGI 를 쓰는 의미가 있다 |
| 일반 `def` + 동기 드라이버 | FastAPI 가 스레드 풀에서 돌려주므로 **이것도 안전하다**. 블로킹 라이브러리를 쓸 수밖에 없다면 오히려 이쪽이 맞다 |
| `async def` + 동기 드라이버 | **최악.** 루프를 막는다 |

세 번째가 함정이다. 문법은 통과하고 테스트도 통과하는데 부하가 걸려야 드러난다.

## 테스트에서 주의한 것

동시성 테스트에서 **세션을 공유하면 진짜 동시성이 아니라 순차 실행이 된다.**
`tests/conftest.py` 의 `gather_isolated` 는 요청마다 별도 세션(=별도 커넥션)을 열어
실제 경쟁을 재현한다. 이걸 놓치면 통과하는 척만 하는 테스트가 된다.
